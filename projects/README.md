# 阶段作品与验收

每个阶段交一个能跑、能被别人复现的东西。验收标准写在下面，做到就打勾。

## 阶段二 · 学习数据报告器

产物：`report.py`，读 `stage2/data/study.csv`，输出：

- 总时长、两个科目的平均时长与平均正确率（数字必须和教材一致：430 / 36.0 / 0.710 / 50.0 / 0.816）
- `results/summary.json`
- 一条命令能跑：`python report.py`

验收：
- [ ] 输出数字与教材一致
- [ ] `summary.json` 能被重新读回
- [ ] 缺文件时给出明确错误，不抛裸 Traceback
- [ ] README 写两条命令

## 阶段三 · 单机 Agent

产物：`agent.py --goal "..."`，包含：
- 两个以上工具，走白名单
- 失败重试一次，两次失败记 error
- 对话写进 `agent.db`
- 每步写 `agent.log`
- `evaluate.py` 报通过率

验收：
- [ ] 一条命令跑出结果
- [ ] 日志能看到每一步
- [ ] 关掉重开，历史还在
- [ ] 评测数字可复跑
- [ ] 工具失败时程序不崩，且说明原因

## 阶段四 · 服务化

产物：`service.py`，提供 `POST /chat`：
- 请求带 `session_id`，两个会话互不串
- 并发上限 2，超出排队
- `/metrics` 返回请求数、失败数、平均耗时
- 超配额返回 429
- `/health` 返回 ok / stopping

验收：
- [ ] 两个 session 的历史互不可见
- [ ] 5 个并发请求的峰值并发为 2
- [ ] 打满配额后返回 429
- [ ] 收到停止信号后先停止接新请求
- [ ] 密钥只在环境变量里

## 通用扣分项

- 路径写死成某台机器
- 日志或数据库提交进仓库
- 只有 print，没有可核对的数字
- 报错时没有明确原因
